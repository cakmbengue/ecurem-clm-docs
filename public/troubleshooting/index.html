Dépannage

Diagnostiquer en suivant le workflow réel : cible → job → résultat → validation → émission → déploiement.

Dans cette pageDiscoveryAgentValidationRenewalSupport

Discovery

  • Job Pending longtemps : vérifiez qu’un job précédent n’est pas encore actif et consultez le Journal du job.
  • Timeout : testez résolution DNS, route, pare-feu et port TLS.
  • 0 certificat : confirmez qu’un service TLS est réellement présent sur le port.
  • Résultats partiels : contrôlez Max Targets per Scan, timeout et périmètre.

Agent Discovery

  • Offline : service local, sortie HTTPS, DNS, heure système.
  • Enrollment token invalid : générez un nouveau jeton à usage unique.
  • Scan local vide : testez les cibles depuis la machine Agent elle-même.

Validation de domaine

  • DNS : droits du compte, zone, propagation.
  • HTTP : route publique et contenu de challenge.
  • Échec répété : ne relancez pas sans corriger la cause.

Renewal

  • Validation échouée : problème avant émission.
  • Demande de certificat échouée : fournisseur ou données de politique.
  • Certificat disponible mais non déployé : certificat émis mais non servi sur TLS.
  • Déploiement non confirmé : vérifiez point de terminaison, port et mécanisme d’installation.
  • Aucune nouvelle exécution : une exécution peut déjà être active.

Préparer une demande de support

Fournissez l’organisation, le nom de la configuration/politique, l’heure approximative, le domaine/cible, l’identifiant de job ou d’historique et le message d’erreur visible.

Ne fournissez jamais de mot de passe, token API, clé privée ou secret DNS dans un ticket.
