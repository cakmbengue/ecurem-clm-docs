Private Discovery and Sensors

Extend discovery into internal networks using an Ecurem Sensor, reusable private scan configurations and work orders strictly bounded to an authorized scope.

On this page1. Operating model2. Sensor3. Private scan configuration4. Work order5. Results and evidence6. Observed protocols7. Security8. Troubleshooting

1. Operating model

A private scan follows a controlled chain: Sensor → configuration → work order → submission → run → observations. Configuration defines what is authorized to be assessed; observations describe what was actually found.

Do not confuse authorized scope with observed assets. An authorized CIDR does not mean every address or service exists.

2. Sensor

The Sensor is installed in the authorized environment and communicates with Ecurem CLM using outbound HTTPS. Windows and Linux runtimes are distributed by Ecurem. The interface shows the Sensor name, status, version and last communication.

Treat enrollment information as secret and never include it in screenshots or tickets.

3. Private scan configuration

A configuration can define CIDR networks, exclusions, TCP ports, host limits and collectors. Start with a small scope, validate routing and firewall rules, then expand progressively.

4. Work order

A work order represents an execution assigned to a Sensor. It retains the authorized scope, execution state, attempts and available metrics. Use its identifier to correlate results precisely.

5. Results and evidence

Validated observations can feed endpoints and Cryptographic Inventory. Evidence & lifecycle views expose source, observation state, confidence, first/last observation dates and, for X.509, available validity information.

6. Observed protocols

Ecurem CLM distinguishes observed protocol families — for example HTTP, SMTP, IMAP, POP3, SSH, unidentified TCP and TLS — from version details such as TLSv1.2 or TLSv1.3.

7. Security

  • Assess only explicitly authorized targets.
  • The Sensor remains bound to its organization.
  • Users see only data permitted by their rights.
  • Tokens, machine identifiers and sensitive technical payloads are not public documentation data.

8. Troubleshooting

  • Sensor offline: check local service, DNS, clock and outbound HTTPS.
  • 0 observations: check CIDR, exclusions, ports, firewall and whether a service is actually present.
  • Work order pending: check Sensor communication and state.
  • Unexpected result: compare authorized scope with observation details rather than inferring from the complete network.
