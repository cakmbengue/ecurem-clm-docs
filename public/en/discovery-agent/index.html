Discovery Agent

Run local Discovery inside customer networks and monitor Agent health from Ecurem CLM.

On this page1. When to use it2. Enrollment3. Status4. Local scans5. Network & security6. Troubleshooting

1. When to use it

Use the Agent for private networks, RFC1918 addresses and services that are not reachable from the SaaS service.

2. Enrollment

Create an enrollment for the target organization and assign an Agent name. Enrollment credentials are short-lived and single-use. During registration the Agent sends a machine identifier, version, network interfaces and configuration; the server binds it to the enrollment organization and returns an Agent authentication token.

Do not reuse expired/consumed enrollment credentials and never place an Agent authentication token in support tickets.

3. Status

Review name, organization, version, interfaces, status and last heartbeat. Heartbeats are used to maintain online/offline visibility.

4. Local scans

Local scan configurations belong to an Agent. Configure only CIDRs and ports reachable from that machine, then follow results in the Agent and Discovery views.

5. Network & security

  • Outbound HTTPS to Ecurem CLM is required.
  • The Agent must reach target ports.
  • Arbitrary inbound exposure is not required for SaaS communication.
  • Keep CIDR scope limited to approved networks.

6. Troubleshooting

  • Invalid/expired enrollment token: create a new enrollment.
  • Agent offline: check service, DNS, outbound HTTPS and system clock.
  • No local results: validate routing, firewall, CIDR and target ports from the Agent host.
