Discovery

Configure scans, choose the right target type, monitor jobs and interpret certificates actually observed on the network.

On this page 1. Quick scan or persistent configuration? 2. Run a quick scan 3. Create a Discovery configuration 4. Choose scan type 5. Targets and ports 6. Limits and timeouts 7. Subdomain discovery 8. Monitor a job 9. Read results 10. Scheduling 11. Common errors

1. Quick scan or persistent configuration?

Quick Scan is suited to a one-time test or investigation. Ecurem CLM creates a manual configuration and immediately queues a job.

A persistent Discovery configuration is better for a scope that should be saved, rerun or scheduled.

2. Run a quick scan

  • Scan name.
  • Organization.
  • Scan type.
  • Targets: one domain, IP address or CIDR network per line.
  • TLS ports: defaults to 443,8443,9443.
  • Maximum targets: 1–1000, initial value 100.
  • Timeout per target: 1–60 seconds, initial value 10.
  • Discover subdomains.
Domain example: choose a domain scan, enter example.com, keep 443,8443, and enable subdomain discovery if required.
Network example: choose a network scan and enter 10.20.30.0/24.

3. Create a Discovery configuration

The full form exposes: Configuration Name, Description, Organization, Scan Type, Schedule, Active Configuration, Target Domains, Network Ranges, Ports to Scan, Max Targets per Scan, Delay Between Scans, Timeout per Target, Scan Common Subdomains and Verify SSL Certificates.

At least one target domain or network range is required.

4. Choose scan type

  • Domain scan: DNS names; CIDR ranges are rejected.
  • Network scan: IP/CIDR targets; DNS names are rejected by Quick Scan.
  • Hybrid scan: where enabled, combines domain enumeration and network-level observations for a domain scope.

5. Targets and ports

Target Domains accepts one domain per line or comma-separated values. Network Ranges expects CIDR notation. Ports to Scan expects comma-separated integers between 1 and 65535.

Scope: include only domains, addresses and networks your organization is authorized to assess.

6. Limits and timeouts

  • Max Targets per Scan: controls per-run workload; full configurations validate up to 10,000.
  • Delay Between Scans: 0–3600 seconds.
  • Timeout per Target: 1–300 seconds in the full configuration form.

7. Subdomain discovery

When enabled, Discovery can expand candidate identities using in-scope DNS identities, certificate SANs and, depending on scan mode, Certificate Transparency and HTTP crawl observations.

8. Monitor a job

Job information includes status, targets scanned, certificates found, new certificates, error count, start time, duration and progress. Use the job log for detailed technical events.

Pending or running jobs can be cancelled. A second concurrent job for the same configuration is not allowed.

9. Read results

Each result records target, port, target type, status, observed certificate data and any error message. Result states include Success, Failed, Timeout and Error.

10. Scheduling

Active configurations can be scheduled hourly, daily, weekly or monthly. The scheduler skips configurations that already have a pending or running job.

11. Common errors

  • No target configured: add at least one domain or network.
  • Invalid port: use 1–65535.
  • Domain scan with CIDR: switch scan type or remove the network.
  • Network scan with hostname: use IP/CIDR targets only.
  • No certificate found: verify DNS, routing, target port and actual TLS availability.
  • Many timeouts: reduce the scope and validate connectivity before increasing timeouts.
