Politiques de Renewal

Transformer les règles métier de renouvellement en déclencheurs, actions, contrôles de validation et étapes de workflow compréhensibles.

Dans cette page1. Champs principaux2. Déclencheurs3. Actions4. Validation5. Étapes6. Exemple concret

1. Champs principaux

Une politique contient notamment : Nom, Description, Activée, Type de certificat, Type de déclencheur, Valeur du déclencheur, Action, Fournisseur, Méthode de validation, Nombre de tentatives, Intervalle entre tentatives, Pré-validation requise, Validation post-renouvellement, options de forçage/émission, workflow et organisation.

2. Déclencheurs

  • Jours avant expiration : lance l’action lorsque le certificat entre dans la fenêtre définie.
  • Niveau de risque : cible selon l’évaluation de risque.
  • Validation de domaine : réagit au besoin de revalidation.
  • Manuel seulement : aucune exécution automatique basée sur le déclencheur.

3. Actions

  • Renouvellement automatique.
  • Notification seulement.
  • Révision manuelle.
  • Validation de domaine.

4. Validation

Les méthodes disponibles sont DNS, HTTP, Email et Auto-détection. Les paramètres de retry contrôlent le nombre de tentatives et l’intervalle. Activez la pré-validation lorsque le contrôle du domaine doit être confirmé avant la demande de certificat, et la validation post-renouvellement pour confirmer le résultat après émission/déploiement.

5. Étapes

Les étapes peuvent couvrir validation de domaine, demande de certificat, approbation fournisseur, test d’installation, notification ou script personnalisé. Chaque étape possède un ordre, un caractère obligatoire et un timeout.

6. Exemple concret

Politique « TLS Prod »
Déclencheur : 30 jours avant expiration.
Action : renouvellement automatique.
Validation : DNS.
Pré-validation : activée.
Workflow : Validation du domaine → Demande de certificat → Test d’installation.
Validation post-renouvellement : activée.

Commencez sur un petit groupe de certificats correctement tagués avant d’étendre la politique.
