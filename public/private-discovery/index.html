Discovery privé et Sensors

Étendre la découverte aux réseaux internes avec un Sensor Ecurem, des configurations de scan réutilisables et des work orders strictement limités au périmètre autorisé.

1. Modèle opérationnel

Le scan privé suit une chaîne contrôlée : Sensor → configuration → work order → soumission → run → observations. La configuration définit ce qui est autorisé à être analysé ; les observations décrivent ce qui a réellement été trouvé.

Ne confondez jamais le périmètre autorisé et les actifs observés. Un CIDR autorisé n’implique pas que chaque adresse ou service existe.

2. Sensor

Le Sensor est installé dans l’environnement autorisé et communique avec Ecurem CLM par HTTPS sortant. Les versions Windows et Linux sont distribuées par Ecurem. L’interface affiche le nom du Sensor, son état, sa version et sa dernière communication.

Traitez les informations d’enrôlement comme des secrets et ne les placez jamais dans une capture ou un ticket.

3. Configuration de scan privé

Une configuration peut définir des réseaux CIDR, exclusions, ports TCP, limites d’hôtes et collecteurs. Commencez avec un périmètre réduit, validez le routage et le pare-feu, puis élargissez progressivement.

4. Work order

Le work order représente une exécution demandée au Sensor. Il conserve le périmètre autorisé, l’état d’exécution, les tentatives et les métriques disponibles. Utilisez son identifiant pour corréler précisément les résultats.

5. Résultats et preuves

Les observations validées peuvent alimenter les endpoints et l’Inventaire cryptographique. La vue Preuves & cycle de vie indique notamment la source, l’état d’observation, la confiance, les dates de première/dernière observation et, pour X.509, les informations de validité disponibles.

6. Protocoles observés

Ecurem CLM distingue les familles de protocoles observées — par exemple HTTP, SMTP, IMAP, POP3, SSH, TCP non identifié et TLS — des détails de version tels que TLSv1.2 ou TLSv1.3.

7. Sécurité

  • Utilisez uniquement des cibles explicitement autorisées.
  • Le Sensor reste rattaché à son organisation.
  • Les utilisateurs ne voient que les données permises par leurs droits.
  • Les tokens, identifiants machine et payloads techniques sensibles ne sont pas des données destinées à la documentation publique.

8. Dépannage

  • Sensor hors ligne : vérifier service local, DNS, heure et HTTPS sortant.
  • 0 observation : vérifier CIDR, exclusions, ports, pare-feu et service réellement présent.
  • Work order en attente : vérifier la communication du Sensor et son état.
  • Résultat inattendu : comparer le périmètre autorisé au détail des observations plutôt que d’inférer à partir du réseau complet.
