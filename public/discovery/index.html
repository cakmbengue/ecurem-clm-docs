Discovery

Discovery réduit les angles morts en combinant l’observation réseau/TLS des certificats avec Discovery Agent pour les environnements internes et, lorsque la fonction est activée, la découverte cryptographique locale.

1. Deux chemins complémentaires

Discovery réseau/TLS analyse des domaines, adresses IP et réseaux autorisés afin d’identifier les services TLS et les certificats réellement observés.

Discovery Agent exécute les scans depuis le réseau client pour atteindre les environnements privés. Il peut également prendre en charge la découverte cryptographique locale lorsque cette capacité est activée.

Le scan certificat/TLS et la découverte cryptographique locale sont deux traitements distincts. Un problème de collecte crypto ne transforme pas un scan TLS déjà terminé en échec.

2. Discovery réseau/TLS

Utilisez un Scan rapide pour une investigation ponctuelle ou une configuration Discovery persistante pour un périmètre qui doit être conservé, relancé ou planifié.

Selon le type de scan, les cibles peuvent être des domaines, adresses IP ou réseaux CIDR. Les ports TLS et les limites d’exécution permettent de contrôler la charge et le périmètre.

3. Types de scan et périmètre

  • Domain scan : noms DNS dans le périmètre autorisé.
  • Network scan : adresses IP ou plages CIDR.
  • Hybrid scan : lorsqu’il est disponible, combinaison d’énumération de noms et d’observations réseau pour un domaine.

N’ajoutez que des cibles que votre organisation est autorisée à analyser. Commencez avec un périmètre limité puis élargissez-le après validation du routage, des pare-feu et des temps de réponse.

4. Jobs et résultats

Un job expose notamment son statut, sa progression, les cibles analysées, les certificats trouvés, les nouveaux certificats, les erreurs et les événements du journal.

Chaque résultat TLS conserve son contexte d’observation : cible, port, type de cible, statut et données du certificat lorsqu’un service exploitable est rencontré.

5. Discovery Agent

Discovery Agent est destiné aux réseaux privés et services non directement accessibles depuis le SaaS. Il établit une connexion HTTPS sortante vers Ecurem CLM et exécute localement les scans qui lui sont confiés.

Voir la documentation Discovery Agent.

6. Découverte cryptographique locale

Lorsque Activer la découverte cryptographique locale est sélectionné, Discovery Agent analyse les emplacements configurés avec son collecteur local et produit un document CBOM.

L’Agent vérifie que le document est au format CycloneDX 1.7, assainit les métadonnées définies comme sensibles, puis place le résultat dans une file locale avant transmission.

Si la plateforme est temporairement indisponible, le CBOM peut rester dans cette file et être transmis après reconnexion.

7. Alimentation des inventaires

Les observations TLS et certificats peuvent enrichir l’Inventaire classique. Les observations CBOM validées et normalisées alimentent l’Inventaire cryptographique de l’organisation.

Voir Inventaire. · Voir Inventaire cryptographique.

8. Dépannage

  • 0 certificat trouvé : vérifiez DNS, routage, pare-feu, port et présence réelle d’un service TLS.
  • Agent hors ligne : vérifiez le service Agent, DNS, HTTPS sortant et l’horloge système.
  • Transmission CBOM en attente : vérifiez la connectivité et l’autorisation de la fonction cryptographique locale.
