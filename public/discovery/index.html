1. Scan rapide ou configuration durable ?

Scan rapide est adapté à un test ponctuel ou à une investigation. Ecurem CLM crée alors automatiquement une configuration manuelle et place immédiatement un job dans la file de traitement.

Configuration Discovery est préférable pour un périmètre qui doit être conservé, relancé ou planifié. Vous pouvez y définir le nom, l’organisation, le type de scan, la planification, les cibles, les ports et les limites d’exécution.

2. Lancer un scan rapide

Le formulaire Scan rapide contient :

  • Nom du scan : nom lisible permettant de retrouver l’exécution.
  • Organisation : seules les organisations accessibles à votre compte sont proposées.
  • Type de scan.
  • Cibles : un domaine, une adresse IP ou un réseau CIDR par ligne.
  • Ports TLS : par défaut 443,8443,9443.
  • Nombre maximal de cibles : de 1 à 1000 dans le formulaire de scan rapide, valeur initiale 100.
  • Délai d’attente par cible : de 1 à 60 secondes, valeur initiale 10.
  • Découvrir les sous-domaines.
Exemple domaine : choisissez un scan de domaines, saisissez example.com, gardez 443,8443 et activez la découverte des sous-domaines si vous souhaitez que Discovery explore des noms rattachés au domaine.
Exemple réseau : choisissez un scan réseau et saisissez 10.20.30.0/24. Un scan réseau n’accepte pas de nom DNS dans le même formulaire.

3. Créer une configuration Discovery

Une configuration complète expose les champs suivants :

  • Nom de la configuration.
  • Description.
  • Organisation.
  • Type de scan.
  • Planification.
  • Configuration active.
  • Domaines cibles.
  • Plages réseau.
  • Ports à scanner.
  • Max cibles par scan.
  • Délai entre les scans (secondes).
  • Timeout par cible (secondes).
  • Découvrir les sous-domaines courants.
  • Vérifier les certificats SSL.

Au moins un domaine cible ou une plage réseau doit être renseigné. Une configuration active est enregistrée avec un statut actif ; une configuration désactivée est mise en pause.

4. Choisir le type de scan

Le type de scan détermine le format accepté dans le périmètre :

  • Domain scan : domaines et noms DNS. Les réseaux CIDR sont rejetés.
  • Network scan : adresses IP/plages CIDR. Les noms de domaine sont rejetés dans le scan rapide.
  • Hybrid scan : selon la configuration de la plateforme, combine l’énumération de noms et les contrôles réseau pour un domaine.

Ne mélangez pas volontairement des cibles incompatibles : le formulaire valide le périmètre avant de créer le job.

5. Renseigner les cibles et les ports

Domaines cibles accepte un domaine par ligne ou des valeurs séparées par des virgules, par exemple :

example.com
api.example.com

Plages réseau attend des CIDR, par exemple :

192.168.1.0/24
10.10.0.0/16

Ports à scanner attend une liste séparée par des virgules. Chaque port doit être compris entre 1 et 65535.

Périmètre : n’ajoutez que des domaines, adresses et réseaux pour lesquels votre organisation est autorisée à effectuer une découverte.

6. Régler les limites et timeouts

  • Max cibles par scan : limite le nombre de cibles traitées par exécution afin d’éviter une charge excessive. Le formulaire de configuration accepte jusqu’à 10 000, mais une valeur plus petite est recommandée pour les premiers tests.
  • Délai entre les scans : pause entre les cibles, de 0 à 3600 secondes.
  • Timeout par cible : temps maximal attendu pour une cible, de 1 à 300 secondes dans une configuration complète.

Augmenter le timeout n’améliore pas un service inaccessible : vérifiez d’abord DNS, routage, pare-feu et ports.

7. Découverte de sous-domaines

Lorsque Découvrir les sous-domaines courants est activé, Discovery peut enrichir le périmètre à partir des noms trouvés dans le scope. Le moteur exploite notamment les identités DNS observées, les SAN des certificats et, selon le type de scan, des sources comme Certificate Transparency et le crawl HTTP.

Les nouvelles identités restent bornées par le périmètre racine et les limites de la configuration. Discovery n’est pas conçu pour transformer un domaine autorisé en scan arbitraire d’Internet.

8. Suivre un job

Après lancement, ouvrez le job. Les indicateurs disponibles comprennent notamment :

  • Statut : en attente, en cours, terminé, échoué ou annulé.
  • Cibles analysées.
  • Certificats trouvés.
  • Nouveaux certificats.
  • Nombre d’erreurs.
  • Démarré le.
  • Durée.
  • Progression et cible courante lorsque disponibles.
  • Journal du job pour le détail technique.

Un job en attente ou en cours peut être annulé. Une même configuration ne doit pas lancer plusieurs jobs simultanés : si un job est déjà en cours, le nouveau lancement est refusé ou différé.

9. Lire les résultats

Chaque résultat Discovery contient une cible, un port, un type de cible (domaine ou IP), un statut, les données du certificat observé et un message d’erreur éventuel.

Les statuts de résultat comprennent Succès, Échoué, Délai dépassé et Erreur.

  • Success : une observation TLS exploitable a été obtenue.
  • Timeout : la cible n’a pas répondu avant le délai.
  • Failed/Error : consultez le message d’erreur et le Journal du job.

Un certificat observé peut alimenter l’inventaire. Vérifiez cependant le domaine, le port et le contexte avant de considérer qu’un actif découvert doit être géré par Renewal.

10. Planification

Les configurations actives peuvent être exécutées manuellement ou avec une planification. Les intervalles supportés par le planificateur comprennent hourly, daily, weekly et monthly.

Si une configuration possède déjà un job pending ou running, le planificateur ne crée pas un second job concurrent.

11. Erreurs fréquentes

  • « You must specify at least one target domain or network range » : renseignez au moins une cible.
  • Port invalide : utilisez un entier compris entre 1 et 65535.
  • Scan de domaines avec CIDR : changez le type en scan réseau ou retirez le CIDR.
  • Scan réseau avec domaine : utilisez uniquement des IP/CIDR.
  • 0 certificat trouvé : vérifiez le port, la résolution DNS, le routage et la présence réelle d’un service TLS.
  • Beaucoup de timeouts : réduisez le périmètre et vérifiez les flux réseau avant d’augmenter les délais.
  • Job déjà en cours : attendez la fin du job existant ou annulez-le s’il est bloqué.
