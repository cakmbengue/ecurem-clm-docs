Inventaire

Utiliser la Liste des actifs pour distinguer les domaines connus, les certificats réellement observés et les actifs qui nécessitent une action.

1. Ce que montre l’Inventaire

Dans Ecurem CLM, Inventaire ouvre la Liste des actifs. Cette vue regroupe deux onglets : Certificats et Domaines. L’organisation active détermine le périmètre visible.

L’objectif n’est pas seulement de compter les certificats : l’Inventaire sert de point de départ pour comprendre ce qui existe, ce qui expire, ce qui est critique et ce qui doit être géré par Discovery ou Renewal.

2. Onglet Certificats

L’onglet Certificats présente notamment des indicateurs de synthèse comme :

  • Total certificats : certificats visibles dans le périmètre courant.
  • Actifs : certificats considérés comme encore valides/actifs.
  • Expirent bientôt : certificats entrant dans la fenêtre d’expiration surveillée.
  • Critiques : certificats dont l’état ou le risque nécessite une attention prioritaire.

Utilisez cette vue avant Renewal pour confirmer que vous ciblez le bon certificat, sur le bon domaine, dans la bonne organisation.

3. Onglet Domaines

L’onglet Domaines fournit la vue des domaines connus et leur état. Les compteurs permettent notamment de distinguer le total, les domaines actifs et les domaines inactifs.

Un domaine peut exister dans l’Inventaire sans qu’un certificat doive être automatiquement renouvelé. Discovery peut également enrichir l’Inventaire à partir des observations réseau.

4. Comprendre les indicateurs

Les cartes d’état servent à prioriser les opérations :

  • Valide / Actif : aucune urgence d’expiration immédiate, mais le certificat reste à surveiller.
  • Expire bientôt : préparez validation de domaine, politique Renewal et cible de déploiement.
  • Critique : examinez l’expiration, la confiance, l’algorithme, la taille de clé, le contexte TLS et les constats associés.
  • Inactif : vérifiez si l’objet doit être conservé, réactivé ou retiré de votre périmètre opérationnel.

5. Lire une fiche certificat

Ouvrez un certificat pour examiner les informations qui expliquent son état : domaine, sujet, émetteur, numéro de série, dates de validité, empreinte, algorithmes et données de sécurité disponibles.

Lorsque le certificat provient de Discovery, vérifiez aussi le contexte d’observation : cible, port et service. Un même certificat peut être observé à plusieurs endroits sans représenter plusieurs certificats logiques différents.

6. Informations cryptographiques

L’Inventaire cryptographique complète les données X.509 classiques avec les informations disponibles sur :

  • algorithme de signature ;
  • algorithme et taille de clé publique ;
  • version TLS observée ;
  • suite cryptographique observée ;
  • classification classique, hybride ou post-quantique lorsque les éléments techniques permettent de la déterminer ;
  • constats de faiblesse ou de métadonnées manquantes.
L’absence d’une donnée cryptographique ne signifie pas que le certificat est conforme ou non conforme. Elle signifie simplement que la plateforme ne dispose pas encore d’une preuve suffisante pour ce critère.

7. Tags et ciblage

Utilisez les tags pour distinguer les actifs réellement gérés des actifs simplement observés. Une convention courante peut être :

  • prod
  • preprod
  • demo
  • renewal-auto
  • renewal-manual

Avant toute action groupée, vérifiez toujours la liste réelle des certificats sélectionnés.

8. Importer des domaines

Le bouton Importer domaines permet d’alimenter l’organisation avec un ensemble de domaines à suivre. Après import, utilisez Discovery pour observer les services et certificats réellement présents.

Évitez d’importer de très grands périmètres sans gouvernance : définissez propriétaire, finalité et périmètre avant de lancer des scans ou des renouvellements.

9. Workflow recommandé

  1. Importer ou créer les domaines à suivre.
  2. Lancer Discovery sur un périmètre autorisé.
  3. Examiner les certificats trouvés dans l’Inventaire.
  4. Classer les actifs avec des tags.
  5. Identifier les expirations et risques.
  6. Configurer Validation de domaine et Renewal uniquement pour les actifs réellement gérés.
  7. Utiliser Rapports pour suivre la posture et documenter les actions.
